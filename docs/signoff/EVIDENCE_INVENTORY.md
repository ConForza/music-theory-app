# Educational evidence inventory (80 outcomes, 245 templates)

A consolidation of evidence that **already exists**. No curriculum review, generator run or test was repeated to build it. The per-record matrices are generated by `npm run signoff:matrix` (`scripts/signoff-matrix.mjs`, read-only; `npm run signoff:matrix:check` fails if they are stale).

**A class is a statement about how much evidence a teacher has to look at. It is not an approval, and it changes no `qa.status`, `teacherReview` or `contentStatus`.** Every record is still `draft` / `pending`.

## Classification rules

Applied mechanically by the script; a record gets the first rule that matches.

**Template**

* **C: insufficient / not reviewed** if it is used by no node or assessment, **or** has no seeded sample in the teacher pack (a teacher has nothing to inspect).
* **B: requires a focused teacher check** if it has samples but any of: (1) an open, not-owner-answered `OPEN_QUESTIONS` row names it (its id, a lesson it is bound to, one of its concepts or one of its outcomes; Q2 and Q38 are linked to the term-list templates by hand because they name no id); (2) it is one of the four templates corrected after review; (3) it is one of the two Grade 1-level score-reading templates (decision 3); (4) no engine test names it, so its answers rest on E1/E2 only.
* **A: adequate for teacher inspection** otherwise: used, 4 pack samples, an engine test names it, and no open convention question touches it.

**Outcome** (this approves the author's decomposition and its coverage, not each question)

* **C** if no lesson, no assessment section or no bound template.
* **B** if an open question names the outcome, or none of the templates assessed for it is class A.
* **A** otherwise.

Limits, stated so they are not mistaken for findings: links to open questions are structural, so 23 open questions (Q1, Q4-Q7, Q10, Q11, Q13, Q18-Q20, Q23, Q25-Q27, Q29-Q33, Q35-Q37) that name no template, lesson, concept or outcome id are not attached to any record (they are listed with count 0 in the links file and remain open); an engine test that merely names a template (for example a hand-built golden case) counts for E3 even when it is not a full re-derivation, and the CSV gives the line so that can be judged.


To pass it (`packages/curriculum/src/validate.ts`, `checkReleaseClaims`) all of these must be **genuinely** true, and only a real review can make them so:

1. `teacherReview.status: "approved"` with a real `reviewer` and `signedOffAt` in `release.json`.
2. `newerRevisionCheck.result: "none_found"`, after someone checks abrsm.org in a browser (Q1).
3. All 80 outcomes `teacherReview: approved`.
4. All 245 templates `qa.status: approved` (this includes the 8 class-C templates, so the two unused ones must be retired or used first).
5. All 235 nodes `contentStatus: approved`, including the 6 optional enrichment nodes.
6. If `release.status` is set to `approved` it needs 1; a `publishedAt` date needs `status: approved`.

The non-release `npm run validate` passes (structural), and `docs:check` is current. **Private preview is not represented as validator-certified.**
